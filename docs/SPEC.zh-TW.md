# Readback 規格（c0mpiled-18，2026-11-11）

題目：YC Fall 2026 Requests for Startups 的「Multiplayer AI」。

Readback 是「複誦」的意思：塔台下指令後，機師把指令唸回去一次，確認沒聽錯。

## 一句話

兩個人一起指揮同一個 AI agent 時，每句話都看得到：agent 聽懂了嗎？還記得嗎？成品真的照做了嗎？

## 要解決的問題

我和隊友一起讓 AI 做一件事。我補了限制，隊友改了資料，但我們不知道：

1. agent 有沒有完整理解剛才那句話。
2. 它現在照的是誰的版本，前面講過的還記不記得。
3. 這句話什麼時候生效。
4. 它現在在等誰。
5. 成品有沒有真的照我們說的做。

## 誰在用

兩位隊友（Roy、Mia）各開一個瀏覽器視窗，對同一個 agent 說話。agent 把一件工作拆成幾步，一步一步做。

第一批想服務的人：同時用好幾個 coding agent、而且和隊友一起做事的小團隊。這個客群還沒有訪談驗證。

## 功能

### 1. 回條

- 訊息送出後立刻顯示「已送達」。
- 接著 agent 回一張回條，有四欄：聽到什麼、類型（新增、修改、撤回、回答、提問）、何時生效、預計產出。
- 回條產生失敗時，訊息不會消失，會以原話排隊。

### 2. 檢查點：排隊或插話

- 每一步開始前都有一個檢查點。
- 訊息預設排隊，到下一個檢查點才交給 agent。
- 繼續做下去會白做時（正在用的事實被改正，或被叫停），才插話：中斷正在跑的那一步，帶著更正重做。
- 排隊或插話由 agent 提議，隊友可以改成「立刻插話」或「收回」。收回時，這句話在記憶板上造成的改變會一起還原。
- 全部做完之後才送來的訊息，會自動多加一步來處理。
- 小任務的一步只要幾秒，通常來不及插話。插話是給長時間的步驟用的。

### 3. 打字時等待

- 有隊友正在打字時，agent 做完手上這一步，會在檢查點等這句話送出，最多等 15 秒。
- 這是等人，不是放慢模型。模型輸出多快，畫面就顯示多快。

### 4. 記憶板

- 之後的步驟或接手的模型必須遵守的話，會自動釘上記憶板。
- 分三類：限制、決定、核准關卡。
- 釘的是隊友的原話，並記下是誰說的。
- 每一步的 prompt 最前面都原文帶入記憶板，不經過摘要。
- 訊息還在排隊時，對應的那一條標成「待生效」。
- 被新訊息取代的條目不刪除，標成「已取代」。

### 5. 等人處理

- 排計畫時缺具體資料（日期、價格、名字），agent 不亂編，改成提問，最多 2 題，並指定給某位隊友。
- 第 1 步不會被問題擋住，到真的需要答案的那一步才停。
- 隊友說「要我看過才能完成」時，會產生一個核准關卡，指定給那位隊友。
- 回答之後，答案會釘成一條「決定」。

### 6. 成品檢查

- 完成前，拿成品逐條對照記憶板上的限制和決定。
- 每一條顯示有沒有做到，並附上成品裡的那句話當證據。
- 字數和字元數由程式量好交給模型，不讓模型自己數。
- 有沒做到的，agent 多跑一步修正，最多兩次。

### 7. 交棒

- 按一下，把工作交給另一家的模型。
- 交接單由系統從現有狀態組出來，記憶板的原話原封不動帶過去。
- 每條釘選各有一題情境題。接手的模型逐題作答，由原本的模型評分，沒答對的再講一次、再考一次。
- 第二次還是沒答對，交棒失敗，工作留在原本的模型。
- 這是加分功能，不是主線。

### 8. 其他

- 每一步都能看到實際送給模型的完整 prompt。
- 介面和 agent 寫的說明文字可以切換中文或英文。
- 畫面上方有一條「下一步」提示，告訴每個人現在該做什麼。

## 畫面

- 上方是三條跑道：Roy、agent、Mia。agent 跑道是步驟和檢查點。隊友說的話是一個小標籤，用線連到 agent 接住它的地方。虛線是排隊中，實線是已生效。
- 下方三欄：訊息和回條、這一步的產出、等人處理加記憶板加交棒結果。
- 網址加上 `?view=split` 會把兩位隊友的視窗並排。

## 今晚不做

- 登入和權限。只有 Roy 和 Mia 兩個固定身分，所以不能直接放上公開網路。
- 資料庫。工作階段存在記憶體，伺服器重啟就清空。
- 兩位隊友的要求互相矛盾時，由誰決定。
- 多人共同編輯同一段 prompt。
- 用自己的訂閱帳號跑模型（像 T3 Code 那樣驅動本機的 coding agent）。
- 雲端部署。
- 真的把內容發布到外部平台。

## 技術

- 前端：Vite、React、TypeScript。樣式手寫，沒有用元件庫。
- 後端：一個 Node 行程，不用框架。狀態用 Server-Sent Events 推給所有視窗。
- 模型：GMI Cloud 的 API。

## 驗收：90 秒 demo 要跑得出來

範例裡的產品（Acme Timer）、價格和日期都是虛構的。

1. Roy 開一件工作，agent 列出幾步並開始做。
2. Mia 正在打字，agent 在檢查點等她。她說「50 字以內」，拿到回條，這句話釘上記憶板，下一步開始生效。
3. Mia 要求最後要她核准。
4. agent 缺發布日期，問題出現在 Roy 的「等人處理」。Roy 回答後繼續。
5. 做完後 Roy 更正價格，agent 多跑一步。
6. 成品檢查逐條顯示：字數、日期、價格都有做到，並附證據。
7. Mia 核准，工作才算完成。
